# 오늘은, 비둘기.

Vite + vanilla TypeScript + Three.js로 만든 3D 비둘기 광장입니다. 현재는 **내 컴퓨터에서 실험하는 로컬 모드**가 기본입니다. Node.js 24 이상을 사용하세요.

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

빌드: `npm.cmd run build`. 카메라는 localhost 또는 HTTPS에서 사용할 수 있습니다. 개발 서버는 자동 실행하지 않습니다.

지금은 `npm.cmd run dev`만 사용하면 됩니다. 별도 저장 서버나 `npm.cmd start`가 필요하지 않습니다. 실행 중인 화면은 새로고침해서 변경을 적용하세요.

## 현재: 로컬 실험 모드

비둘기의 얼굴 이미지·3D 형태·말풍선·생성 순서는 이 브라우저의 IndexedDB(`pigeon-local-v1`)에 저장됩니다. `/api`로 저장 요청을 보내지 않습니다. 새로고침과 브라우저 재실행 후에도 복원되며, 같은 주소의 다른 탭에서도 공유합니다. 다른 브라우저·기기와는 공유하지 않습니다.

최대 40마리, 41번째부터 오래된 순서로 교체, 촬영, 부리 변형, 충돌 회피, 말풍선 기능은 그대로 동작합니다. 브라우저의 사이트 데이터를 삭제하면 로컬 실험을 초기화할 수 있습니다. 저장 공간은 주소에 따라 구분되므로 `localhost`와 `127.0.0.1`, 또는 다른 포트에서는 별도의 광장이 나타납니다. 이전 서버 DB와 로컬 실험 데이터는 서로 분리되며 자동 이동하지 않습니다.

## 나중에 서버 연결하기

기존 서버 기능은 남아 있지만 기본 개발 모드에서는 비활성화됩니다. 배포를 준비할 때 `npm.cmd run build:server`로 서버 모드 빌드 후 `npm.cmd start`를 사용하면 됩니다. 기본 포트는 3000이며 웹 화면과 저장 API를 함께 제공합니다. 서버 모드로 개발하려면 `npm.cmd run dev -- --mode server`를 사용합니다. `.env.server`의 `VITE_STORAGE_MODE=server`가 명시적으로 서버 저장을 활성화합니다.

## 서버 모드의 저장과 공유

비둘기 목록, 생성 순서, 얼굴 영역을 잘라낸 JPEG 이미지, 변형된 3D 정점·UV를 서버의 `data/pigeons.sqlite`에 저장합니다. 새 방문자와 새로고침한 브라우저도 저장된 비둘기를 복원하며 서버를 재시작해도 유지됩니다. 얼굴 검출은 촬영한 브라우저에서 수행하고, 다른 방문자는 저장된 형태를 복원합니다.

최대 40마리를 서버에서 관리합니다. 41번째부터 가장 오래된 개체의 이미지·모델을 삭제하고 새 개체로 교체하며, 동시 생성도 SQLite 트랜잭션으로 처리합니다. 요청 재전송은 같은 ID로 중복 생성되지 않습니다. 이미 접속한 브라우저에는 약 3초마다 추가·교체 내역이 반영됩니다. 얼굴·형태·생성 순서는 공유하지만 개체의 이동 좌표와 걷기·비행 시뮬레이션은 각 브라우저에서 계산합니다.

실제 배포에는 Node.js를 실행할 수 있는 서버와 **영구 디스크**가 필요합니다. 정적 파일만 호스팅하거나 배포 때 로컬 디스크가 초기화되는 환경에서는 데이터가 유지되지 않습니다. `PIGEON_DB_PATH` 환경 변수로 영구 볼륨의 DB 경로를 지정할 수 있고 `PORT`, `HOST`로 서버 주소를 설정합니다. 현재 구성은 하나의 서버/공유 SQLite 파일을 사용하는 배포용입니다. `data/`는 Git에 포함하지 않습니다. DB를 직접 백업할 때는 서버를 중지한 뒤 파일을 복사하거나 SQLite 백업 기능을 사용하세요.

서버 모드에서 생성한 비둘기만 서버에 남습니다. 로컬 실험 데이터와 서버 데이터는 자동으로 합쳐지지 않습니다.

## 사용

선택한 저장소에 비둘기가 없을 때만 빈 아스팔트에서 시작합니다. `Become a Pigeon` → 카메라 권한 허용 → 원형 셔터를 누르면 얼굴을 검출하고 저장한 뒤 비둘기를 생성합니다. 부리 길이는 시스템이 무작위로 정합니다. 새 비둘기는 얼굴을 보여준 뒤 배회합니다. 마우스 드래그로 시점을 회전하고 휠로 확대하며 모바일은 터치로 조작합니다. 수평선 너머는 흰색이며 장식 구조물과 상시 안내 문구는 없습니다. 촬영 창도 아이콘으로 조작하며 오류가 발생했을 때만 안내 문구가 표시됩니다.

MediaPipe가 검출한 468개 얼굴 점에 사진을 매핑하고 코·입 주변 정점을 앞으로 돌출시켜 개인화된 3D 얼굴을 만듭니다. 사진 한 장 기반의 스타일화된 얼굴 표면이며 정밀한 전방위 두상 복원은 아닙니다. 몸통은 절차적으로 생성한 도시 비둘기입니다. 걷기 시 머리 전진/유지 동작과 양발 교대, 저공 비행 시 날갯짓과 착지를 구현했습니다.

## 말풍선

비둘기 생성 후 `Wanna Say Something?` 버튼이 나타납니다. 클릭하면 가로로 긴 흰 입력창이 열립니다. 한글·영어 입력이 확정될 때 방금 입력한 글자 바로 뒤에 짧은 `9`·점 묶음이 간헐적으로 추가됩니다. 기존 문장 사이의 임의 위치에는 끼어들지 않고 입력을 멈추면 더 생기지 않습니다. 직접 입력한 문자와 공백만 최대 50자로 계산하며 자동 삽입 문자는 제외합니다. 직접 입력한 `9`와 점은 일반 문자처럼 계산합니다. 자동 문자 위치도 저장하므로 새로고침 후 같은 글자수를 유지합니다. 연속된 `9`는 4개까지입니다. 한글 IME 조합 중에는 값이나 커서를 바꾸지 않으며, 조합 종료 직후 다음 조합이 시작되면 이전 처리 예약을 취소해 중복 입력을 방지합니다. Backspace·Delete·선택 삭제 중에는 자동 삽입을 멈춰 정상적으로 지울 수 있습니다.

자동 문자 생성 간격은 키 이벤트 횟수가 아닌 확정된 글자 수를 기준으로 하며, 최초 생성 이후 약 7~10글자마다 생성합니다. 한글 조합 전환 중에도 이 수를 누적해 영어와 비슷한 빈도를 유지합니다. 자동 문자를 지운 뒤 다시 입력하면 생성을 재개합니다.

내 말풍선은 즉시 표시되고 입력을 잠시 멈추면 자동 저장합니다. Enter를 한 번 누르면 진행 중인 한글 조합까지 확정한 뒤 저장하고 입력창을 닫습니다. 닫기 버튼으로도 닫을 수 있습니다. 말풍선은 걷기, 머리 흔들기, 비행과 카메라 회전에 맞춰 머리 위를 따라갑니다. 새로고침 후에도 복원되며, 다른 방문자와 공유하는 것은 서버 모드에서만 동작합니다.

이 브라우저에서 가장 최근 생성한 비둘기에 말을 붙입니다. 브라우저는 비둘기 ID와 편집용 토큰을 로컬 저장소에 보관하며 서버에는 토큰 해시만 저장합니다. 공개 ID만으로 다른 사람의 말을 수정할 수 없습니다. 해당 비둘기가 40마리 제한으로 교체되면 말풍선과 편집 버튼도 사라집니다. 브라우저 저장소를 지우거나 다른 기기로 이동하면 이전 비둘기의 편집 권한은 복원되지 않습니다. 기존 DB는 메시지 컬럼을 자동 추가하며 기존 비둘기를 보존합니다.

현재 로컬 모드에서는 촬영된 얼굴 영역과 비둘기 형태를 브라우저에만 저장합니다. 서버 모드를 켜면 서버에 저장되어 다른 방문자에게 공개됩니다. 전체 카메라 원본 프레임은 저장하지 않습니다. 얼굴 모델과 WASM은 `public/models`에서 로드합니다. 개체가 교체되면 해당 이미지·모델을 선택한 저장소에서 삭제하고 브라우저의 GPU 자원도 해제합니다.

## 구조

- `src/main.ts`: 화면, 촬영 즉시 생성, 권한·오류 처리
- `src/world.ts`: 아스팔트, 조명, 비둘기 모델, 무작위 이동과 애니메이션
- `src/flock-physics.ts`: 근접 회피, 고도별 충돌, 접촉 분리·반발, 겹치지 않는 생성 위치
- `src/face.ts`: 얼굴 검출, 사진 UV 매핑, 부리 형태 변형
- `src/shared-flock.ts`: 서버 저장, 접속 시 복원, 목록 동기화
- `src/local-flock.ts`: 서버 없이 IndexedDB 저장·복원·40마리 교체
- `src/storage-mode.ts`: 기본 로컬/선택적 서버 저장 모드
- `src/speech.ts`, `src/speech-text.ts`: 말풍선 입력, IME 처리, 랜덤 문자 삽입, 길이 제한
- `server/store.ts`: SQLite 영구 저장, FIFO 교체, 중복 요청 처리
- `server/api.ts`: 조회·생성 API와 입력 검증
- `server/index.ts`: 운영 서버와 정적 파일 제공
- `vite.config.ts`: 개발·미리보기 서버에 동일한 저장 API 연결
- `src/style.css`: 반응형 화면
- `public/models/`: MediaPipe 모델과 WASM 런타임
- `templates/`: 추후 템플릿 보관 공간

MediaPipe 런타임은 설치된 `@mediapipe/tasks-vision`의 `wasm` 폴더와 같은 버전을 유지해야 합니다. 런타임을 업데이트하면 해당 파일도 복사하세요.

비둘기 생성 후 우측 상단의 `Remove Your Pigeon`을 누르고 `OK`로 확인하면 가장 최근에 만든 비둘기로 카메라가 가까이 이동한 뒤 1초 대기하고, 비둘기가 블랙홀로 회전하며 사라집니다. 효과가 끝나면 약 0.7초 동안 삭제 전 카메라 시점으로 돌아옵니다. 현재 로컬 모드에서는 IndexedDB, 서버 모드에서는 소유자 토큰을 확인한 뒤 SQLite에서 얼굴과 말풍선까지 삭제합니다. 저장소 삭제 성공 후 효과를 재생하므로 새로고침해도 복원되지 않습니다. 확인창은 Cancel 또는 Escape로 취소할 수 있습니다. 시스템의 동작 줄이기 설정에서는 회전 없이 짧게 가라앉습니다.

여러 비둘기를 만들었으면 최신 개체부터 하나씩 삭제할 수 있고, 본인 개체가 모두 사라질 때까지 삭제 버튼이 유지됩니다. 소유 정보는 개체별로 저장되어 새로고침 후에도 이어집니다. 삭제하면 말풍선 입력 대상도 다음 본인 개체로 전환됩니다. 기존 로컬 개체의 소유 정보는 IndexedDB에서 복구합니다. 이전 서버 모드에서 덮어쓰여 사라진 과거 토큰은 복구할 수 없지만, 이번 변경 이후 생성하는 개체들의 토큰은 모두 보관됩니다.

서버 공개 전 다중 사용자 확인 기준: 신규 방문자에게도 서버에 남아 있는 다른 사람의 비둘기들은 그대로 표시합니다. 다만 본인이 만든 비둘기가 없다면 `Become a Pigeon` 버튼만 표시합니다. `Wanna Say Something?`과 `Remove Your Pigeon`은 현재 광장에 본인 소유 비둘기가 최소 한 마리 있을 때만 표시하며, 본인 개체를 모두 삭제하거나 40마리 제한으로 모두 교체되면 다시 숨깁니다. 서로 독립된 브라우저 세션에서 이 조건을 확인하고, 다른 사람의 개체 수를 본인의 버튼 표시 조건으로 사용하지 않습니다. 이 기준은 추후 서버 연결·배포 점검 때 검증하며 현재 로컬 실험 모드는 유지합니다.

영문은 [Ubuntu Light 공개 배포본](https://github.com/google/fonts/tree/main/ufl/ubuntu)을 `public/fonts/Ubuntu-Light.ttf`에서 직접 제공합니다. 글자 폭 110%를 적용하고 자간은 기본값을 사용합니다. `Wanna Say Something?` 버튼의 텍스트에는 10도 기울임을 적용합니다. 한글은 시스템 굴림체(Gulim)를 사용하며, 굴림이 설치되지 않은 환경에서는 기본 sans-serif 글꼴로 표시됩니다. 배포 라이선스는 `public/fonts/UFL.txt`에 포함되어 있습니다.

## 확인

평상시에는 개체별 무작위 대기 시간에 따라 모이 쪼기, 배설, 드문 짝짓기 행동이 섞입니다. 한 번에 행동하는 개체는 보통 전체의 약 22%(최대 5마리)로 제한합니다. 짝짓기는 첫 시도까지 45~60초를 기다리며, 이후 2~5마리일 때 45~60초마다 약 25~34% 확률로 시도합니다. 개체가 많으면 시도 간격은 35~50초, 확률은 최대 45%입니다. 실패한 시도도 다음 간격까지 기다리고, 참여한 개체는 종료 후 100~160초 동안 다시 짝짓기하지 않습니다. 올라타는 위치는 꼬리에 가까운 등 뒤쪽입니다. 동시에 한 쌍만 행동합니다. 가까운 상대가 없으면 짝짓기를 시작하지 않으며, 행동 중에는 분홍 하트가 떠오릅니다. 모이를 쪼는 동안에는 실제 얼굴 정점의 높이를 확인해 부리가 바닥에 들어가지 않도록 보정합니다. 새로고침으로 복원한 비둘기는 충돌하지 않는 무작위 위치와 방향에서 즉시 움직입니다. 잠시 멈춘 뒤 아이보리색 액체가 낙하해 불규칙한 모양으로 바닥에 번지고 약 18~28초 후 사라지며 최대 12개만 유지합니다. 푸들 등장이나 개체 삭제·교체 시 진행 중인 행동을 해제합니다. 행동과 배설물은 화면 연출이며 저장 데이터를 변경하지 않습니다. `npm.cmd run test:behavior`로 동시 행동 제한, 자세 복원, 짝 행동 해제, 배설물 수명과 정리를 검사합니다.

삭제 버튼 아래의 검정 푸들 아이콘을 누르면 푸들이 가까이 접근한 비둘기부터 날아갑니다. 주변 비둘기의 이륙에도 약간의 시차를 두고 연쇄적으로 반응합니다. 푸들 퇴장 4초 후부터 걷기·비행, 동시·개별 복귀를 섞어 무작위 속도와 순서로 돌아옵니다. 복귀 시작 시 생성·말하기·삭제와 카메라 조작을 먼저 해제하고, 푸들 재실행만 복귀 완료까지 기다립니다. 이 연출은 현재 화면에서만 실행되며 저장된 비둘기와 말풍선을 삭제하지 않습니다. `node scripts/smoke.mjs 얼굴사진.jpg --poodle`로 거리 기반 퇴장·혼합 복귀·버튼 조기 해제와 데이터 보존을 확인할 수 있습니다.

`npm.cmd run test:physics`는 정면 회피, 겹침 해소, 비행·착지 충돌, 40마리 생성 위치와 120초 교차 이동을 검사합니다(Node.js 22.6 이상 필요). 충돌은 개체를 둘러싼 단순 충돌 영역으로 계산하며 깃털 하나하나의 정밀 충돌은 아닙니다.

`npm.cmd run test:persistence`는 디스크 재연결 후 복원, FIFO, 중복 요청, 동시 생성, 잘못된 데이터 거부를 검사합니다.

`npm.cmd run test:speech`는 한글·영어 길이 제한, 연속 9 제한, 편집 권한, 비둘기 교체 시 말풍선 삭제, 기존 DB 마이그레이션을 검사합니다. 브라우저 검사에는 IME 조합 보호, 말풍선 추적, 다른 방문자에게 말 공유, 권한 없는 수정 거부도 포함됩니다.

`npm.cmd run build` 후 `node scripts/smoke.mjs 얼굴사진.jpg --capacity`로 로컬 모드 검사를 실행합니다(로컬 Edge 필요). API 요청을 차단한 상태로 촬영·IndexedDB 저장·말풍선·새로고침·다른 탭·40마리 제한을 확인하고 API 요청이 0회인지 검사합니다. 별도 브라우저에는 데이터가 공유되지 않는 것도 확인합니다.

서버 모드 검사는 `npm.cmd run build:server` 후 `node scripts/smoke.mjs 얼굴사진.jpg --capacity --server`입니다. 모든 브라우저 검사는 격리된 임시 테스트 서버와 데이터를 사용하고 종료 시 정리하며 개발 서버나 실제 DB는 사용하지 않습니다. 실제 카메라 장치 확인은 별도로 필요합니다. 검사 후 `npm.cmd run build`로 기본 로컬 빌드를 복원하세요.
