# 성능 최적화와 호환성 점검

2026-10-13 작업. 기존 그래픽과 기능을 유지하는 범위만 적용했습니다.

## 적용한 변경

- 비둘기 이동·목 움직임·충돌 계산과 마법사 무리 제어에서 임시 벡터와 배열을 재사용합니다. 계산 순서, 이동 속도, 충돌 반복 횟수는 유지합니다.
- 비둘기의 몸통·깃털·발가락처럼 로컬 변환이 고정된 메시의 변환 행렬을 캐시합니다. 부모 그룹의 걷기·날기·기울기 애니메이션과 움직이는 목은 계속 갱신합니다.
- 인간·마법사 표면 생성 시 불필요한 중간 배열을 없애고, 상체 갱신 직후 같은 부모 아래의 바지를 갱신할 때 관절 행렬 계산을 중복하지 않습니다. 메시 좌표와 법선 계산은 유지합니다.
- 비둘기·방문자·효과가 없는 정지 광장은 화면이 바뀌었을 때만 GPU에 그립니다. 카메라 조작, 크기 변경, GPU 컨텍스트 복구 후 다시 그립니다. 비둘기가 있는 화면의 프레임 수는 줄이지 않습니다.
- 숨겨진 문서에서는 GPU 렌더링을 생략합니다. 기존의 배경 효과 완료 처리는 유지합니다.
- 손 추적의 `createImageBitmap`이 없는 환경에서는 기존 DOM 캔버스 호환 모드로 진행합니다. 지원되는 환경의 Worker 처리와 모델은 유지합니다.
- PNG 5개는 IDAT 압축만 다시 했습니다. 원본의 압축 해제된 픽셀/필터 바이트와 색상·메타데이터 청크를 그대로 유지합니다. 해상도와 화질은 동일합니다.

## 측정 결과

| 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| PNG 5개 합계 | 5,921,459 bytes | 5,366,055 bytes |
| 40마리 이동 계산 500회에서 Vector3.clone 호출 | 1,496,598회 | 85회 |
| 같은 계산의 단일 실행 CPU 시간 | 약 92.1ms | 약 48.7ms |

PNG 전송량은 555,404 bytes(약 9.4%) 줄었습니다. 압축된 파일만 작아지므로 GPU의 텍스처 메모리 사용량은 같습니다. CPU 시간은 이 컴퓨터에서 수행한 이동·충돌 계산 비교이며 전체 사이트 FPS나 다른 기기의 속도 개선율을 뜻하지 않습니다.

동일 난수와 입력으로 비둘기 40마리를 600단계 이동시켜 위치, 속도, 목·머리·날개·다리 상태를 비교했습니다. 최대 차이는 0입니다. 해당 비둘기 장면의 640×360 화면과 4096px 그림자를 비교한 결과 다른 RGBA 채널은 0개입니다. 이 비교가 사이트의 모든 효과·조명·기기에서 픽셀 동일성을 전수 검증한 것은 아닙니다.

## 브라우저 검증 범위

Windows에서 Playwright 브라우저 엔진을 실행했습니다. 아래 표의 모바일·태블릿은 실제 기기가 아닌 화면 크기와 터치 입력 에뮬레이션입니다. Chromium 자동 테스트는 헤드리스 환경의 소프트웨어 WebGL 허용 옵션을 사용하며, 사이트 설정은 바꾸지 않습니다.

| 엔진 | 데스크톱 1440×900 | 스마트폰 390×844 | 태블릿 820×1180 |
| --- | --- | --- | --- |
| Chromium / Chrome 계열 | 통과 | 통과 | 통과 |
| 설치된 Microsoft Edge | 통과 | 통과 | 통과 |
| Firefox | 통과 | 통과 | 통과 |
| WebKit / Safari 계열 | 통과 | 통과 | 통과 |

각 조합에서 3D 렌더링, 휠 또는 두 손가락 확대, 말풍선 표시, 화면 방향 변경에 따른 리사이즈, 정지 광장의 불필요한 렌더링 방지, 숨겨진 문서의 렌더링 중단과 복귀를 확인했습니다. 강제 컨텍스트 복구 확장을 지원하는 데스크톱 엔진에서는 GPU 컨텍스트 복구도 확인했습니다.

추가 검증:

- 물리·개체 행동·텍스트·저장 테스트 25개 통과.
- 40마리에서 확대·축소, 말풍선 꼬리 결합, 카메라 정지, 블랙홀 삭제 테스트 통과.
- 인간 걷기·포즈, 치와와 반응·복귀, 자동차 충돌·후면 퇴장·복귀 테스트 통과.
- 마법사 40마리 제어, 로프·모자·외알 안경, 데스크톱/세로 화면 종료, 카메라 해제·권한 거부 테스트 통과.
- Chromium/Edge·Firefox·WebKit에서 한글 IME 이벤트 재현과 9/점 생성·삭제·저장 테스트 통과.
- 같은 세 엔진에서 실제 손 추적 모델 실행, Worker 및 호환 경로, 카메라 정리 테스트 통과. WebKit의 합성 카메라는 실제 촬영 장치 대신 캔버스 영상 어댑터를 사용합니다.
- `npm run build` 통과.

실제 iOS, iPadOS, Android, macOS의 GPU·카메라·OS 키보드와 장시간 발열은 이 환경에서 직접 측정하지 못했습니다. Samsung Internet 등 개별 모바일 브라우저 앱을 실행한 것도 아닙니다. 엔진 테스트는 호환성 문제를 줄이는 검증이며 모든 OS·기기에서 정상 작동한다는 보증은 아닙니다. 기존 3D 표현에는 WebGL2와 하드웨어 지원이 필요하고, 카메라에는 HTTPS와 사용자 권한이 필요합니다.

## 적용하지 않은 최적화

해상도/DPR, 그림자 4096px, 안티앨리어싱, 메시·깃털 수, 텍스처 화질, 보이는 화면의 프레임 수, 애니메이션과 손 추적 품질을 낮추는 방식은 적용하지 않았습니다. 이런 방법은 저성능 기기의 GPU 부하를 더 줄일 수 있지만 요청한 동일한 비주얼·기능 조건을 만족하지 못할 수 있습니다.

현재 그래픽 품질로 다수의 3D 개체를 계속 움직이는 동안 모든 기기에서 버벅임이나 발열을 완전히 없애는 것은 보장할 수 없습니다.

## 검증 실행

PowerShell에서 `npm.ps1`이 차단되는 경우 `npm.cmd`를 사용합니다. 테스트는 임시 로컬 HTTP 서버를 열고 종료하며 개발 서버를 실행하지 않습니다.

```powershell
npm.cmd run build
npm.cmd run test:compatibility
npm.cmd run test:physics
npm.cmd run test:behavior
npm.cmd run test:mobile-speech
npm.cmd run test:hand-tracking
npm.cmd run test:human
npm.cmd run test:wizard
```

브라우저 테스트에는 Playwright의 Chromium, Firefox, WebKit 및 설치된 Edge가 필요합니다. PNG를 재압축하려면 `node scripts/optimize-png.mjs`를 실행합니다. 더 작아지는 경우에만 저장합니다.
